## Workspace JSON

**Settings → Sync & backup → Export JSON** writes the whole workspace: pages,
documents, canvases, graph nodes and edges, tags, captures, templates, decks,
cards, comments, and attachments.

**Import JSON** reads a file produced by that export. It only accepts a file
from the same workspace, merges the records into the local database, and queues
them for sync, so an import reconciles rather than replaces.

## GitHub

**Settings → Sync & backup → GitHub** connects an account, Vercel-style:
click **Connect GitHub**, approve the OAuth App on github.com, and GitHub
returns you to Settings. The account then appears with its repository scope,
and the import and sync dialogs offer a searchable repository picker.

The token is encrypted with the deployment secret and kept on the server. It is
never sent to the browser: import and sync call a narrow proxy that only
forwards the repository and contents endpoints they need. Disconnecting deletes
the stored token.

Connecting is opt-in for a deployment. Register a GitHub OAuth App with the
callback URL below, then set:

```bash
GITHUB_CONNECT_ENABLED=true
GITHUB_CLIENT_ID=Iv1…
GITHUB_CLIENT_SECRET=…
# Optional; defaults to ${BETTER_AUTH_URL}/api/github/callback
GITHUB_REDIRECT_URI=https://lattice.example.com/api/github/callback
```

The callback must be reachable by the browser that completes the sign-in. When
no client secret is configured, Lattice falls back to GitHub's device flow: it
shows a short code, opens `github.com/login/device`, and polls until you
approve. That path needs no callback URL at all.

With the flag off, the GitHub card stays hidden and the dialogs keep their
manual token field. With it on but no client id, the card shows the missing
variables and the callback URL to register instead.

**Settings → Sync & backup → Import from GitHub** pulls a repository's Markdown
into a new notebook.

1. Pick a repository from the connected account, or type `owner/repository`
   directly (a full GitHub URL also works). Private repositories are included
   while connected.
2. Optionally restrict to a folder. Without a connection, add a token for
   private repositories or a higher rate limit; it is used for that request
   only and never stored.
3. Lattice reads the default branch, fetches up to 40 Markdown files, converts
   them to blocks, and creates one page per file.

Imported pages record `source: github`, the repository, and the original path as
properties, so you can trace a page back to its file. Titles come from the file
name (`code-of-conduct.md` becomes “code of conduct”, `media/readme.md` becomes
“media README”). Images stay linked by their original URL.

This import records each file's path, branch, blob SHA, and the hash of the body
it round-trips to. That bookkeeping is what lets the repository be synced both
ways afterwards.

## Two-way Git sync

Settings → Sync & backup → **Sync with Git** compares the pages bound to a
repository against its current tree. Pick the repository from the connected
account and the stored credential is used automatically; otherwise type it and
paste a token. Checking costs one request, and each page comes back as one of:

To fill an empty repository, tick **Include local pages that are not in this
repository** before checking. Every page is then listed as **New here** with a
path generated from its title under the prefix, and publishing the first one
creates the repository's first commit.

| State | Meaning | Action offered |
| --- | --- | --- |
| In sync | Remote SHA and local body both match the last sync. | None |
| Local ahead | Only the body changed here. | Push |
| Remote ahead | Only the blob changed on the remote. | Pull |
| Conflict | Both changed since the last sync. | Keep mine, or take remote |
| New here | Never pushed. | Publish |
| Deleted remotely | The file is gone from the remote. | Push to recreate it |

A push sends the blob SHA it expects to replace, so a file that moved on the
remote is refused with a conflict rather than overwritten. A file deleted
remotely never deletes the page — the page is the copy you still have.

### Scheduled sync

The dialog can save the repository config in this browser and run the same
two-way sync on a schedule: every 15 minutes, 30 minutes, an hour, or four
hours, checked while Lattice is open and online. With a connection, the saved
config holds no token and the scheduled pass goes through the server; without
one, the pasted token is stored in this browser so the background run can use
it. Scheduled passes only push local edits and pull remote edits — conflicts,
deleted-remote files, and never-published pages still wait for a person.
**Forget saved credentials** removes the stored config and token.

## Obsidian and Notion vaults

Settings → Sync & backup → **Import a vault** reads a folder of Markdown notes.
Every folder becomes a notebook under a root notebook named after the vault, so a
nested vault keeps its shape.

The importer reads the conventions those tools write:

- Frontmatter `title` wins over the file name, and `aliases` become extra link targets.
- `tags` in frontmatter and `#inline` tags in the body become workspace tags.
- Notion's 32-character hash suffix and Obsidian's `01 ` ordering prefixes are stripped from names.
- `[[wiki links]]` are matched by full path, then file name, then alias, and rewritten into real page links so the graph draws edges between the notes.
- `![[embeds]]` are treated as transclusions and left alone, as are links inside fenced code blocks.

A link that resolves to nothing keeps its literal `[[text]]`, and a name shared by
two notes is never guessed at — both are reported instead of silently linking the
wrong page.

### Vault export

**Settings → General → Export Markdown vault** writes the workspace as a `.zip`
of Markdown files that the importer can read back:

- Pages are grouped under their notebook path, with invalid filename characters
  replaced and duplicate names numbered.
- Frontmatter carries `title`, `tags`, and `icon`.
- Page links are written as `[[Title]]`, so a vault survives a round-trip through
  Obsidian, Notion, or another Markdown tool and returns as linked pages.
- Attachments are not bundled; images keep their served URLs.

## Browser extension

`extensions/lattice-clip` is a Manifest V3 extension that puts the page in front of you into the knowledge inbox. Click the toolbar icon to capture a title, URL, and note, or right-click a page, link, or selection and choose **Save page to Lattice**. It opens quick capture with those fields pre-filled — nothing is sent to the developer, and the extension has no host permissions.

Set the Lattice URL once in the popup; it is remembered with `chrome.storage.sync`. There is no default — until it is saved, saving a page opens the setup panel instead of a link. For a local instance that is `http://localhost:3101`.

```bash
node extensions/lattice-clip/build.mjs           # validate, stage, and package
node extensions/lattice-clip/build.mjs --check   # validation only
```

The build refuses to package a manifest that a store would reject: over-long name or description, a version outside the allowed shape, missing or non-PNG icons, popup assets that did not ship, or permissions beyond the reviewed allow-list. It writes `dist/unpacked/` for **Load unpacked**, a zip with fixed timestamps (same inputs, same `sha256`), and a build report for release notes. `STORE_LISTING.md` and `PRIVACY.md` in the same directory carry the listing copy, justifications, and disclosures the store asks for.

## Markdown

Individual pages export as Markdown from the page actions menu, and Markdown
mode round-trips a page through the Markdown serializer. Tables, callouts,
diagrams, and API request blocks export as fenced blocks or quoted summaries
rather than being dropped.
