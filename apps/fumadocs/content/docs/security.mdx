Security is enforced at the API boundary and mirrored in the UI, not trusted from the client.

## Authentication

Better Auth handles email/password sessions and Expo session forwarding. Cookies are `HttpOnly`, `SameSite=None`, `Secure` for cross-origin web and desktop flows. Native stores the session in SecureStore and forwards it explicitly.

## Workspace scoping

Every workspace-scoped procedure resolves membership server-side using the session user and `x-workspace-id`. Handlers derive the workspace from that verified membership; payload workspace ids are not trusted.

For sync writes:

- Existing entity ids are checked against the workspace.
- Parent chains (notebook, parent page, canvas) are validated.
- Page moves reject cycles.
- Cross-tenant id collisions are rejected, not upserted.

## Authorization

Role rank gates mutations. Page access additionally considers creator, visibility, and explicit resource permissions.

- Private page content is removed from pull/snapshot for other members.
- Explicitly shared pages require a matching resource permission.
- Guests cannot see workspace-wide resources.

## Share tokens

- 32 random bytes, base64url encoded.
- SHA-256 hash stored in Postgres.
- Expiry and revocation checked on every public request.
- Public payloads never include sibling pages, workspace member data, or private linked titles.
- `Referrer-Policy: no-referrer` is set on the public share layout.

## Rate limiting

Express applies a per-IP budget to RPC and auth endpoints, with a stricter budget for auth. Share lookups are additionally constrained by expired/revoked checks.

## Uploads

`POST /uploads` requires a valid session, accepts one raw file body up to 25 MB, writes to a server-owned directory with a generated filename, and serves only the file URL. Files are not executed.

### PDF text extraction and OCR

PDF captures can be extracted from the inbox. The API reads the stored file, extracts selectable text with PDF.js (`unpdf`), and appends it to the capture through the sync change log. Files above 25 MB are refused.

When a PDF has no text layer, or for images, the browser does the OCR instead: the stored file is downloaded with the session cookie, pages are rasterized locally with `pdfjs-dist`, and text is recognized with `tesseract.js`. Nothing is uploaded for OCR and no provider is required — the trade-off is that the first run downloads the OCR engine and English model from jsDelivr unless `NEXT_PUBLIC_TESSERACT_CDN` points at a self-hosted mirror. Up to 15 pages are read per file, and the recognized text lands through the normal capture change log. Audio captures can additionally be transcribed by the server's provider when one is configured.

## Retention

Deletes are soft deletes. Each workspace can set a trash window (30/90/180/365 days, or keep forever) in Settings → General. A scheduled server job then permanently removes soft-deleted rows older than that window and appends tombstone changes, so clients converge on the same result. There is intentionally no manual purge button; an instant purge needs its own op semantic to stay consistent with local-first clients.

## Explicitly deferred

The schema and service boundaries include hooks for, but this release does not claim:

- end-to-end encryption,
- SSO / SCIM,
- legally binding enterprise retention or legal hold,
- a full audit-grade compliance program.

Those are product-level programs, not UI states. See [Roadmap](/docs/roadmap).
