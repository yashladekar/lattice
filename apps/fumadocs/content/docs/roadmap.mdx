## Implemented in this pass

- Multi-tenant workspaces, organizations, invites, roles, and resource visibility — settable from the page context panel and the notebook menu.
- Local-first IndexedDB repository, outbox, snapshot, cursor pulls, conflict preservation.
- Block editor with slash menu, mentions, page links, embeds, synced blocks, database block, Mermaid diagrams, page properties, block actions (duplicate, turn into, delete, copy block link), favorites, comments, versions, Markdown mode, and focus mode.
- Infinite whiteboard with shapes, notes, freehand, interactive connectors, linked notes, nested canvases, layers, group resize, node-to-page conversion, outline generators (mind map, flowchart, concept map), snapshots, templates, presentation, and export.
- Derived knowledge graph with typed edges, canvas-link edges, filters including recency and cluster coloring, local neighborhood view, a minimap, temporal playback, orphan detection, manual relations, natural-language graph questions answered locally, and dashed AI suggestions recorded with AI provenance on accept.
- Universal capture inbox, quick capture, URL preview, tag and related-note suggestions with explicit approval, capture-to-page, email ingestion through an inbound webhook, audio capture with provider transcription, and PDF text extraction.
- Workspace JSON export/import, per-page Markdown, GitHub Markdown import with two-way Git sync (including an optional schedule), an Obsidian-style Markdown vault export for round-trips, and Obsidian and Notion vault import.
- Learning decks, generated and manual cards, SM-2 review, quizzes, mastery, paths, gaps, and opt-in due-card reminders while the app is open.
- Optional AI with citations and local fallback: summarize, explain, compare, examples, connections, cards, mind map, outdated pages, and gaps, plus an embedding-based semantic index for Ask retrieval.
- Dashboard widgets with reorder and visibility controls, command palette, tabs with a split pane, keyboard-first navigation, search, timeline, trash, and a dismissible first-run checklist.
- Share links for pages, canvases, notebooks, and graphs; public read-only surfaces.
- Comments with a mention picker, notifications, presence heartbeats, audit log, devices with revocation, and a suggested-edit review queue.
- Signed webhook deliveries for page, canvas, capture, and comment events, queued from the change log with retries and a test action.
- Web, PWA shell with an update prompt, Tauri packaging config with OS-browser link handling, self-host Docker with a persistent uploads volume.
- Expo companion with capture, browse, search, review, **Markdown page editing**, and a persisted offline query cache. Editing uses a DOM-free Markdown subset parser and the same revision-aware `page.saveDocument` path as the web app, so a stale edit returns a conflict instead of overwriting another device.
- Fumadocs product/architecture documentation.

## Shipped: live co-editing

- Yjs co-editing for page documents and whiteboards over a WebSocket relay, with a room per resource.
- Live cursors and selection presence in the editor.
- Conflict-free concurrent typing; both peers converge without conflict snapshots.
- Whiteboard edits merge per field, so two people moving different shapes, or editing different fields of one shape, both survive.
- Presence and live cursors on the whiteboard, at canvas coordinates.
- The document is persisted per resource and flushed when the last peer leaves, so a session outlives its room and an edit made just before a tab closes is not lost.

## Shipped: discussion at scale

- Discuss filters locally with pure domain helpers (`comment-threads.ts`): status chips with counts, body/author search that also matches replies, block-anchored narrowing, and grouping by block with the biggest group first.
- Threads collapse replies after two with a "show more" control, lists page 20 at a time, and each block group jumps the editor to its anchor — so a page with a hundred discussions stays readable.
- Open threads sort first and then newest first, so a new reply never reorders the list under the reader.

## Shipped: object types

- Workspaces define object types with a typed property schema — text, number, date, select, checkbox — in **Settings → Object types**.
- Pages opt in from the Info tab; the assigned schema renders typed inputs that write through the normal page property path, so values sync and export with the page.
- Definitions are validated on the server too: keys are derived from labels, duplicate and reserved keys dropped, and the schema is capped at 40 fields.

## Shipped: query console

- Read-only SQL over workspace-scoped views, with a result grid and schema browser.
- Write and schema-escape attempts rejected by a tested validator, and by Postgres itself.

## Shipped: retention and purge

- Every workspace chooses a trash window (Keep forever, 30, 90, 180, or 365 days) in Settings → General.
- A server-side job runs on a schedule: soft-deleted rows past the window are permanently removed, in dependency order, and tombstone changes are appended to the change log so every device reflects the purge.
- This is deliberately the shape that works. Immediate manual purge is still not a button: a client that dropped rows locally would disagree with the server and resurrect content on the next pull, so that needs its own op semantic and apply path.

## Shipped: SCIM provisioning

- SCIM 2.0 Users and Groups under `/scim/v2`, authenticated with workspace bearer tokens (hashed, shown once, independently revocable, five active per workspace).
- Create, update, deactivate, and deprovision members, with filter matching on `userName`/`externalId`/`displayName`, PATCH support, and `409 uniqueness` on repeats.
- Group membership assigns roles (`admin`, `editor`/`member`, `viewer`); ownership is never granted over SCIM, and the owner cannot be deprovisioned.
- Provisioned changes flow through the change log and audit log, so they reach devices and the audit trail like in-app changes.

## Shipped: SSO

- Per-workspace OIDC connection with Authorization Code + PKCE, nonce, discovery, and JWKS-verified ID tokens; the client secret is stored encrypted with a deployment-derived key.
- Email-domain discovery on the login page, a nonce-checked callback that creates a real better-auth session, and an allow-listed redirect back to the app.
- Sign-in requires an active, provisioned membership; unverified emails are refused. Verified end-to-end against a local test provider, including the replayed-state, unknown-workspace, open-redirect, and unprovisioned guards.
- SAML is not implemented; OIDC covers the common providers.

## Next: enterprise

- Legal hold scoped to a workspace, notebook, or page, with a server-generated export bundle.
- BYOK for AI: workspace-owned provider credentials, encrypted at rest and masked on read.

## Shipped: duplicate review

- Near-duplicate pages found by exact title, drifted title, or repeated body, with the evidence recorded per group.
- A Duplicates tab that shows each group with excerpts and archives the ones you do not keep, recoverable from Trash.

## Shipped: local vectors

- Hybrid retrieval needs no provider: lexical ranking is blended with a local hashed TF-IDF vector score (stemmed tokens, phrase bigrams, 512 dimensions, L2-normalized), cached per workspace index and rebuilt only when local data changes.
- It widens recall past exact tokens — a query for "habits" finds a note that says "habit" — while lexical scoring still decides between documents that share words.
- Runs offline, in a worker, and on a phone with no download, and is honest about its limits: it is a lexical-vector index, not a neural model. Provider embeddings still power the server-side semantic index when configured.

## Shipped: version playback

- Graph playback now replays **links**, not just nodes: a new `page.versionTimeline` endpoint returns each readable version's page-link ids (version bodies are parsed server-side and never sent), and the graph filters `PAGE_LINK` edges by each note's newest version at or before the scrub point.
- A reference added in version 4 and removed in version 6 appears only between those edits; pages without a version in the window keep their live links instead of pretending they had none.
- The playback bar captions the latest version at the scrub point, or says `no saved versions` when the workspace has none.
- The timeline is capped at the most recent 200 workspace versions and filtered by page access, so private notes stay out of another member's playback.

## Shipped: attachment OCR

- Images and scanned PDFs are read in the browser with `tesseract.js`; PDF pages with a text layer are used directly and only the rest are rasterized with `pdfjs-dist`.
- Picking a PDF tries the server's text-layer extraction first and falls back to OCR automatically; image captures get an **OCR text** action.
- Recognition is offline-capable apart from the engine download, capped at 15 pages, and the result is appended to the capture as an "OCR text" section through the normal change log.

## Shipped: browser extension

- MV3 extension (`extensions/lattice-clip`) that sends the current page, link, or selection to quick capture, with the Lattice URL stored in `chrome.storage.sync`.
- `node build.mjs` validates the manifest against store limits (name/description length, version shape, icon sizes and PNG magic bytes, popup assets, permission allow-list) and packages `dist/unpacked/` plus a deterministic zip with a recorded `sha256`.
- Listing copy, permission justifications, data-usage answers, a privacy policy, screenshot list, and a release checklist ship next to the code, so a store submission is copy-paste rather than a rewrite.
- Store upload and review are the remaining manual step; the package itself is reproducible and verifiable.

## Shipped: plugin blocks and canvas tools

- A manifest can declare **blocks** (inserted into the editor from the page actions menu) and **canvasTools** (offered in the whiteboard's generate menu), each capped and validated like the rest of the manifest.
- Blocks are real document nodes: input, output, error, and run time are stored in the node, so a block syncs, versions, and exports with the page. Output renders as plain text by default, or as sanitized Markdown when the block declares `output: "markdown"`.
- Canvas tools return Markdown that the host lays out as a mind map, flowchart, or concept map — plugins shape content, the host owns rendering.
- Passive run context (`ctx.input()`, `ctx.canvas()`, `ctx.tool()`) is data handed over by the host; capability checks still gate every callable API, and canvas data is only passed when `graph:read` is granted.

## Shipped: plugin runtime

- Capability-checked worker isolation, with per-capability consent and revocation.
- Ambient network and database access removed before plugin code loads.
- A curated in-app directory of audited plugins: word count, TODO extraction, related notes, and structure tools (an editor block plus a canvas tool).
- Install from an HTTPS URL: the bundle is fetched, its manifest validated, and its requested capabilities shown for approval before anything installs.

## Shipped: automation rules

- Up to five named webhook destinations per workspace in **Settings → Automations**, each with its own event subscription.
- Conditions narrow a destination: title contains, notebook, page type, operation (saved/deleted), and author.
- Filters are evaluated at enqueue time, so unmatched events never reach the delivery queue; a condition on a field the event lacks excludes it.
- Recent deliveries show which destination received what, alongside the existing signed payloads, retries, and test action.

## Shipped: live sessions and out-of-band writes

- Document ops carry an origin. Only a `session` snapshot keeps the stale-revision exemption that co-editing needs; every other writer (suggested-edit accept, version restore, Markdown save, import, `page.saveDocument`, plugin write) is revision-checked and turns a stale write into a `SyncConflict` instead of losing silently to a live peer.
- The change log keeps that origin, and a live editor refuses to persist when the local document advanced from a write it did not make — it warns and offers **Reload note** rather than putting the older body back.
- **Reload note** calls `sync.resetCollab`, which drops the stored CRDT and any live room so peers reconnect and seed from the stored document.
- Still not attempted: merging an out-of-band write into a live CRDT. The session resets rather than merges, which costs a reconnect but never picks a silent winner.

## Explicit non-goals for this release

This build does not claim production-grade E2E encryption, SSO/SCIM, or app-store signing. The data model and service boundaries are designed so these can be added without replacing the knowledge model.
