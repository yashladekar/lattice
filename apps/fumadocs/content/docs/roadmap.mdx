## Implemented in this pass

- Multi-tenant workspaces, organizations, invites, roles, and resource visibility — settable from the page context panel and the notebook menu.
- Local-first IndexedDB repository, outbox, snapshot, cursor pulls, conflict preservation.
- Block editor with slash menu, mentions, page links, embeds, synced blocks, database block, Mermaid diagrams, page properties, block actions (duplicate, turn into, delete, copy block link), favorites, comments, versions, Markdown mode, and focus mode.
- Infinite whiteboard with shapes, notes, freehand, interactive connectors, linked notes, nested canvases, layers, group resize, node-to-page conversion, outline generators (mind map, flowchart, concept map), snapshots, templates, presentation, and export.
- Derived knowledge graph with typed edges, canvas-link edges, filters including recency and cluster coloring, local neighborhood view, a minimap, temporal playback, orphan detection, manual relations, natural-language graph questions answered locally, and dashed AI suggestions recorded with AI provenance on accept.
- Universal capture inbox, quick capture, URL preview, tag and related-note suggestions with explicit approval, capture-to-page, email ingestion through an inbound webhook, audio capture with provider transcription, and PDF text extraction.
- Workspace JSON export/import, per-page Markdown, GitHub Markdown import with two-way Git sync (including an optional schedule), an Obsidian-style Markdown vault export for round-trips, and Obsidian and Notion vault import.
- Learning decks, generated and manual cards, SM-2 review, quizzes, mastery, paths, gaps, and opt-in due-card reminders while the app is open.
- Optional AI with citations and local fallback: summarize, explain, compare, examples, connections, cards, mind map, outdated pages, and gaps, plus an embedding-based semantic index for Ask retrieval.
- Dashboard widgets with reorder and visibility controls, command palette, tabs with a split pane, keyboard-first navigation, search, timeline, trash, and a dismissible first-run checklist.
- Share links for pages, canvases, notebooks, and graphs; public read-only surfaces.
- Comments with a mention picker, notifications, presence heartbeats, audit log, devices with revocation, and a suggested-edit review queue.
- Signed webhook deliveries for page, canvas, capture, and comment events, queued from the change log with retries and a test action.
- Web, PWA shell with an update prompt, Tauri packaging config with OS-browser link handling, Expo companion with a persisted offline query cache, self-host Docker with a persistent uploads volume.
- Fumadocs product/architecture documentation.

## Shipped: live co-editing

- Yjs co-editing for page documents and whiteboards over a WebSocket relay, with a room per resource.
- Live cursors and selection presence in the editor.
- Conflict-free concurrent typing; both peers converge without conflict snapshots.
- Whiteboard edits merge per field, so two people moving different shapes, or editing different fields of one shape, both survive.
- Presence and live cursors on the whiteboard, at canvas coordinates.
- The document is persisted per resource and flushed when the last peer leaves, so a session outlives its room and an edit made just before a tab closes is not lost.

## Next: collaboration depth

- Granular block-level comments and discussion resolution at scale.

## Shipped: object types

- Workspaces define object types with a typed property schema — text, number, date, select, checkbox — in **Settings → Object types**.
- Pages opt in from the Info tab; the assigned schema renders typed inputs that write through the normal page property path, so values sync and export with the page.
- Definitions are validated on the server too: keys are derived from labels, duplicate and reserved keys dropped, and the schema is capped at 40 fields.

## Shipped: query console

- Read-only SQL over workspace-scoped views, with a result grid and schema browser.
- Write and schema-escape attempts rejected by a tested validator, and by Postgres itself.

## Shipped: retention and purge

- Every workspace chooses a trash window (Keep forever, 30, 90, 180, or 365 days) in Settings → General.
- A server-side job runs on a schedule: soft-deleted rows past the window are permanently removed, in dependency order, and tombstone changes are appended to the change log so every device reflects the purge.
- This is deliberately the shape that works. Immediate manual purge is still not a button: a client that dropped rows locally would disagree with the server and resurrect content on the next pull, so that needs its own op semantic and apply path.

## Next: enterprise

- SSO and SCIM.
- End-to-end encryption with key custody and recovery.
- Legal hold, export on demand.
- Organization-managed storage regions and BYOK.

## Shipped: duplicate review

- Near-duplicate pages found by exact title, drifted title, or repeated body, with the evidence recorded per group.
- A Duplicates tab that shows each group with excerpts and archives the ones you do not keep, recoverable from Trash.

## Next: knowledge intelligence

- Semantic search without a provider (local embeddings).
- Temporal graph playback across note versions.

## Next: capture and ingestion

- Browser extension distribution.
- Attachment OCR for scanned PDFs and images.

## Shipped: plugin runtime

- Capability-checked worker isolation, with per-capability consent and revocation.
- Ambient network and database access removed before plugin code loads.
- A curated in-app directory of audited plugins: word count, TODO extraction, and related notes.
- Install from an HTTPS URL: the bundle is fetched, its manifest validated, and its requested capabilities shown for approval before anything installs.

## Next: platform ecosystem

- Custom blocks and custom canvas tools from plugins.
- Automation rules on top of the webhook event stream (conditions, filters, destinations).

## Explicit non-goals for this release

This build does not claim production-grade E2E encryption, SSO/SCIM, or app-store signing. The data model and service boundaries are designed so these can be added without replacing the knowledge model.
