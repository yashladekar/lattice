## Writing model

The editor is TipTap 3 with a Notion-like block experience. Top-level blocks receive stable `blockId`s through the UniqueID extension. Those ids anchor comments, live sync blocks, and source references for generated cards.

A page has two records: metadata (`Page`) and the document (`PageDocument`). The editor autosaves JSON into the local document, recomputes plain text and page-link edges, then queues a sync op.

## Menus

| Trigger | Menu |
| --- | --- |
| `/` | Block inserter, grouped by basic, rich, media, and knowledge blocks |
| `[[` | Link another page |
| `@` | Mention a page, teammate, or date |
| Selection | Bubble toolbar for formatting and block actions |
| Block hover | Drag handle for reordering, plus an actions menu |

### Block actions

Hovering a block reveals the drag handle and a small actions menu:

- **Duplicate block** and **Delete block** operate on the hovered block.
- **Turn into** converts it between paragraph, headings, lists, quote, and code.
- **Copy block link** copies a URL that carries the block id, so a reference can
  be pasted anywhere.

Block ids come from the UniqueID extension, the same ids that anchor comments
and transclusions.

## Blocks

Paragraphs, H1–H4, bulleted / numbered / task lists, toggles, quotes, callouts, dividers, code with syntax highlighting, tables, images, bookmarks, YouTube embeds, equations, page links, page embeds, synced blocks, and a structured database block.

The database block supports table, list, board, gallery, and calendar views over the same field/row JSON. It is intentionally lightweight: a structured block inside a page, not a separate product surface.

### Fields

Fields are authored directly on the block:

- **Add a field** from the header and pick a type: text, number, date, select,
  or checkbox.
- Click a field name to **rename** it inline.
- Each field's menu changes its **type** or **deletes** it (values for that
  field are removed with it).
- Select fields have an **Edit options** dialog; options drive the select cell,
  board columns, and calendar grouping.

## Page links and backlinks

A `pageLink` node stores the target page id and display title. On save Lattice derives:

- a `REFERENCES` edge from source node to target node,
- backlink membership for the target,
- graph connectivity,
- link suggestions for related pages.

Removing a link soft-deletes its derived edge. Manual typed relations are separate and never removed by link cleanup.

## Sub-pages

A page can contain other pages. The hierarchy is stored on `Page.parentId`, so a sub-page is a normal page with a parent — it keeps its own document, tags, comments, versions, and graph node.

- **Create** one from the **Sub-pages** list at the bottom of a page, the `+` on a sidebar page row, `/sub-page` in the body, `[[` → **Create …**, or **Page actions → New sub-page**.
- **Navigate** through the nested sidebar tree or the breadcrumb trail; opening a child expands its ancestors, and the page's own children are listed under its body.
- **Reorder** by dragging a sidebar page row before or after a sibling, dropping it on another page to nest it, or dropping it on a notebook header to move it there. On touch, long-press a row to start dragging. The list renumbers itself when two neighbours have no integer gap.
- **Move** a page with **Page actions → Move to…**. The picker excludes the page and its descendants, and a page can return to the top level. This is the keyboard path and remains available when dragging is not.
- **Duplicate** a page from its menu or the sidebar and its readable sub-pages come with it, including their documents, properties, and covers. The copy sits next to the source with the same relative order below it.
- **Delete** a parent and its whole subtree moves to Trash together; restoring the parent restores the subtree and the graph edges inside it.

A sub-page inherits its parent's notebook. A private parent creates a private child; otherwise the child is workspace-visible.

## Images and attachments

Images can be referenced by URL or uploaded. **Upload image** in the `/` menu
opens a file picker; pasting or dropping an image file straight into the page
does the same thing.

Uploads go to the authenticated `/uploads` endpoint, are recorded as workspace
attachments (name, mime, size, URL, page), and sync like any other record. The
image node itself stores the served URL, so a note renders without refetching
the original file.

Only image files are embedded inline. Other files land in the capture inbox via
quick capture instead.

## API requests

The `request` block documents an endpoint and can call it from the page.

- Pick a method, enter a URL, and optionally add headers as `Key: value` lines
  and a body (sent for everything except `GET` and `HEAD`).
- **Send** shows status, duration, size, response headers, and the body, with
  JSON pretty-printed.
- Requests run in your browser, so the target must allow cross-origin requests.
  A blocked request reports the browser's CORS error instead of pretending to
  succeed.
- Responses are transient: they are never saved into the note. Only the request
  definition is stored and synced.

Read-only surfaces, including public shares, show the request definition with a
note that it runs in the workspace. Markdown export writes an `http` fence.

## Templates

**Page actions → Save as template** copies a page's body and properties into a
workspace template. Later edits to the source page do not change it.

Templates are available from **⌘K → New page from template**, alongside the
built-in set: blank, meeting notes, ADR, research brief, project brief, weekly
review, learning note, decision log, and troubleshooting guide. Custom
templates are grouped under **Your templates** and can be deleted from the
picker.

Templates are workspace records, so they sync like any other content. A page
created from a template also inherits the template's properties.

## Diagrams

The `diagram` block renders Mermaid as SVG. It is a first-class block, not a
screenshot, so it stays editable, themes with the app, and prints cleanly.

- Insert from the `/` menu, or use **Page actions → Diagram from outline** to
  turn the page's heading tree into a flowchart.
- Edit the Mermaid source inline; `⌘↵` applies, `Escape` cancels.
- Flowcharts, sequence, class, state, ER, gantt, pie, journey, mindmap, and the
  other Mermaid diagram types all render.
- Mermaid is lazy-loaded, so notes without diagrams never pay for it.

Diagrams render in the editor, the read-only page reader, transclusions, and
public share pages. The mobile companion shows the diagram source instead,
because Mermaid needs a DOM.

Markdown export writes a ```` ```mermaid ```` fence, so diagrams survive a
round-trip through Markdown. A ```` ```mermaid ```` code block imported from
Markdown also renders as a diagram in read-only views.

## Page context

The right panel contains:

- **Info** — page properties, outline, tags, source cards, AI entry points.
- **Links** — backlinks and outgoing page links.
- **Discuss** — page and block-anchored comments with resolve state.

Outline entries jump to their heading in the document, and a block-anchored
comment shows a **Jump to block** chip that scrolls the editor to its anchor.

### Properties

The Info tab lists the page's properties and lets you add, edit, and remove
them. Properties are key/value text pairs stored on the page record, so they
sync and appear in the JSON export.

Creating a page from a template copies the template's properties as well as its
body.

### Object types

Workspaces can define object types (Settings → Object types) with typed fields:
text, number, date, select, or checkbox. Assign one to a page from the Info tab
and the schema renders as labelled inputs backed by the page's properties, so
the values sync and export with the page. The freeform property list stays
available for one-off keys.

### Favorites

The star in the page header stores `favorite: true` in the page's properties.
Favorited pages appear in a **Favorites** section at the top of the sidebar,
and the list is derived from the same property, so it syncs with the page.

## Modes

- **Document** — the default writing surface.
- **Focus** — chrome hidden, wider calm.
- **Markdown** — round-trip the document through a Markdown serializer/importer.
- **Outline** — heading and list structure in the context panel.

The mobile companion has a Markdown editor of its own. It uses a DOM-free subset parser from the domain package (`simpleMarkdownToDoc`) covering headings, paragraphs, bullet/ordered/task lists, quotes, fenced code, rules, and inline bold/italic/code/links; anything else is kept as plain text rather than dropped. Saving goes through `page.saveDocument` with the revision the phone loaded, so an edit made against a stale revision comes back as a conflict — reload or resolve it in the web app, never a silent overwrite.

## Versions

Explicit versions can be saved. Conflicts also create snapshots. Restoring a version always creates a new snapshot first, so history is never destructive.
