## Local stack

| Service | Port | Notes |
| --- | --- | --- |
| Web | 3101 | Next static export / dev server |
| API | 3100 | Express + oRPC |
| Postgres | 5434 | Host mapping of container 5432 |
| Docs | 4000 | Fumadocs |
| Native dev | 8081 | Expo |

The ports are intentionally not 3000/3001 to avoid collisions with other local projects.

## Docker

```bash
pnpm docker:build
pnpm docker:up
pnpm docker:logs
pnpm docker:down
```

Postgres data uses the `notes-learning_postgres_data` volume. API uploads are mounted at `/app/apps/server/storage` through the `notes-learning_uploads` volume, so attachments survive container replacement. Point `UPLOAD_DIR` elsewhere if you mount a different path.

## Web runtime configuration

`apps/web/public/config.js`:

```js
window.__LATTICE_CONFIG__ = window.__LATTICE_CONFIG__ || {
  apiBaseUrl: "",
};
```

Leave `apiBaseUrl` empty to use `NEXT_PUBLIC_SERVER_URL`. Set it for a desktop bundle or a static web deployment pointed at a self-hosted API. The file is loaded before the app bundle.

## Desktop (Tauri)

```bash
pnpm --filter web desktop:dev
pnpm --filter web desktop:build
```

The desktop shell loads the static export. Point `public/config.js` at an HTTPS API for production. Tauri origins (`tauri://localhost`, `http://tauri.localhost`) are trusted by the API.

## Mobile (Expo)

```bash
pnpm --filter native dev
pnpm --filter native ios
pnpm --filter native android
```

Set `EXPO_PUBLIC_SERVER_URL` to the API. The companion supports sign-in, workspace switching, recent/notebook browsing, page reading, capture, search, and card review.

## Backup

1. **Local export** — Settings → Export this workspace (full JSON).
2. **Postgres** — `pg_dump` the database on a schedule.
3. **Uploads** — back up the server storage directory.
4. **Attachments** — attachments are server-hosted after upload; link them to the same backup policy.

IndexedDB is not a backup. Browsers can evict non-persistent origins. Grant persistence in Settings and keep a sync server or regular export.

## AI

Add `AI_BASE_URL`, `AI_API_KEY`, and `AI_MODEL` to the API environment. Keep the provider key server-side. Without it, Ask Lattice runs local retrieval. Set `AI_EMBEDDING_MODEL` (default `text-embedding-3-small`) to control the model used by the optional semantic index.

### ChatGPT plan

Members can connect their own ChatGPT Plus or Pro plan instead of using an API key. The server opens a loopback listener on `127.0.0.1:1455` (falling back to an ephemeral port, path always `/auth/callback`) because OpenAI's Sign in with ChatGPT flow only accepts a loopback redirect. Two consequences for a self-hoster:

- **It only works when the server runs on the same machine as the browser** — local Compose, `pnpm dev`, or the desktop build. A remote server cannot receive the callback. For that case, complete the sign-in locally and use **Export credential** / **Import credential** in Settings, which follows OpenAI's self-hosted VM guidance.
- **Plan usage covers chat only.** It cannot produce embeddings or transcribe audio, so keep `AI_API_KEY` for the semantic index and the inbox transcriber. Without a key, both report that plainly instead of failing silently.

The listener only starts when someone opens the sign-in flow. It is bound to loopback, serves exactly one path, and never returns credentials to the browser. Tokens are encrypted at rest with `BETTER_AUTH_SECRET` as the key material — back that secret up with the database, or existing connections have to be reauthorized.

### Plan mode

`AI_AGENT_ENABLED=true` turns on the experimental planning assistant: Ask can read pages and propose edits, graph links, and flashcards, which a person then applies. It is **off by default**, adds up to six model calls per question, and needs no extra configuration. Set it back to `false` and restart to remove the surface entirely; no data is migrated either way.

### Audio transcription

Audio captures in the inbox can be transcribed when the provider exposes `/audio/transcriptions`. The model comes from `AI_TRANSCRIBE_MODEL` (default `whisper-1`). The server reads the stored upload from `UPLOAD_DIR`, sends it to the provider, and appends the transcript to the capture through the sync change log; files above 25 MB are refused.

## Email capture

Each workspace can generate an ingest token in **Settings → General → Email capture**. Point an email provider's inbound webhook at the API:

```text
POST <API>/ingest/email
x-lattice-ingest-token: <token>
Content-Type: application/json

{"subject":"…","text":"…","html":"…","from":"…","to":"…"}
```

`text` wins over `html`, which is reduced to plain text. Each delivery becomes an `EMAIL` capture in the inbox through the normal sync change log, so every device receives it. Tokens are stored as SHA-256 hashes, can be rotated or revoked, and the endpoint is limited to 30 requests per minute per IP.

## Automations

**Settings → Automations** configures up to five named HTTPS destinations per workspace. Each destination subscribes to its own events and applies condition filters when an event is queued:

| Event | Fires when |
| --- | --- |
| `page.updated` | A page is saved or restored |
| `page.deleted` | A page is trashed or purged |
| `canvas.updated` / `canvas.deleted` | A whiteboard changes state |
| `capture.updated` | A capture is added or organized |
| `comment.updated` | A comment is added or resolved |

Deliveries are queued in the same transaction as the change log, then POSTed by the server with:

```text
x-lattice-event: page.updated
x-lattice-delivery: whd_…
x-lattice-signature: sha256=<hex HMAC-SHA256 of the raw body>
```

- **Operation** — only saves/restores, only deletes, or both.
- **Title contains** — a case-insensitive substring on the changed record's title.
- **Notebooks** and **page types** — narrow to specific notebooks or DOCUMENT/CANVAS/DATABASE pages.
- **Authors** — only changes made by selected workspace members.

A condition on a field the event does not carry (say, a title filter on a comment event) excludes that change, so a narrowed destination stays narrow. Filtering happens at enqueue time, so a non-matching event never reaches the delivery queue.

The signing secret is shown per destination and can be rotated. Failures retry with backoff (1, 5, 15, 60, 240 minutes) up to five attempts; disabled endpoints and non-HTTPS or private-address URLs are cancelled. Test deliveries use `webhook.test`.

Targets must be public HTTPS hosts. Literal private IPs, localhost, and `.local` names are refused before delivery; DNS-based SSRF checks are left to your deployment's egress policy.

## Polar

Polar is opt-in: `POLAR_ENABLED=true` plus a valid access token. Leave it off if you do not need billing; expired billing credentials cannot block signup.
